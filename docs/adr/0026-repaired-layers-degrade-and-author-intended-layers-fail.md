# Repaired layers degrade and author-intended layers fail

In the Output Tile path, Rentile's compatibility profile retains the icon of a symbol layer whose text it removes whenever that icon's geometry does not depend on the text. Such a layer is retained by repair rather than by the style author's intent, and it is treated differently from a layer the author declared as an icon layer: when a repaired layer cannot be compiled, cannot resolve its sprite, cannot acquire its vector source, or cannot evaluate a per-feature property, it is excluded or skipped with a diagnostic, while an author-intended icon layer keeps failing loudly exactly as it always has.

The asymmetry exists because repair changes what gets fetched and compiled. Before it, these layers were excluded before their properties were ever validated and before their sprite, source, or tiles were ever requested, so a style could prepare and render successfully while carrying constructs the profile cannot support and resources the renderer never touched. Retaining them makes all of that reachable for the first time, and a strict contract applied to newly reachable work converts "an icon is missing" into "the style does not prepare" or "the batch does not render" — a strictly worse outcome than the bug being fixed, and one measured against the rolling corpus rather than imagined. A layer carrying `text-optional: true` is the author declaring that the icon stands alone, so it is author-intended and stays strict.

The governing rule is that no style which prepared successfully before repair may fail to prepare after it, and none which rendered may fail to render. Two consequences follow that are easy to mistake for defects. A vector source reachable only through repaired layers is acquired best-effort per tile: its failure neither fails the batch nor consumes the substitution budget, and it is reported as `ICON_LAYER_SKIPPED_SOURCE_UNAVAILABLE` rather than raised. And a per-feature property failure on a repaired layer skips that feature and reports `ICON_FEATURE_SKIPPED` rather than failing the tile. Every degraded path is observable through both `RenderedTile.diagnostics` and the diagnostic sink; silence would make repair indistinguishable from data loss.

Two deliberate exceptions remain in the Output Tile path. A malformed vector source reachable only through a repaired layer still fails preparation, because the alternative weakens a genuine safety property — bare preparation failures surfacing instead of being silently converted into an excluded layer — for a case the rolling corpus does not contain. And an icon whose `icon-text-fit` depends on text extents is excluded from the PNG rather than drawn at sprite size, because that would emit plausible but incorrect geometry.

The Label Candidate path does not remove the text and therefore does not apply that second exclusion. As of `0.6.0`, every visible text-bearing vector symbol layer remains in the label closure, and its candidate can carry the paired icon plus `icon-text-fit`, paint, collision, alignment, and a semantic anchor on the final fitted box for the viewport-owning consumer to resolve with the label's glyph bounds. Sprite imagery remains consumer-owned; the reference names it but does not transport an atlas. Failure to emit a requested paired icon leaves the label available and reports `ICON_FEATURE_SKIPPED`; losing the icon silently would recreate the omission this ADR forbids. See [ADR 0024](0024-label-placement-belongs-to-the-consumer.md) and the [0.6.0 migration guide](../migrations/0.6.0.md).

# Expose decoded DEM texels

Rentile will return the decoded pixels of an elevation Source Tile alongside its encoded bytes, as canonical 8-bit RGBA with straight alpha, and will do so only for DEM tiles. `ValidatedDemTile` gains `texels`; `bytes` is unchanged and remains what a caller hashes for cache identity.

The alternative was leaving every terrain consumer to decode the bytes itself, which in practice means owning decoders for whichever containers providers choose. That is not hypothetical: across a real 34-style corpus, five of the six styles declaring a top-level `terrain` block serve WebP DEM tiles and one serves PNG, so a consumer with a PNG decoder alone reaches one terrain style in six. WebP means VP8L and VP8 on an untrusted-bytes boundary, and Rentile already carries a hardened decoder for exactly that reason. Asking every consumer to carry a second one multiplies the same attack surface across projects that have less reason to be good at it. This does not widen Rentile's own remit: it hands over a decode it already performs rather than taking on new work, and ADR 0024's line still holds elsewhere, since terrain arithmetic, placement and drawing all remain the consumer's.

Nothing is decoded twice. Raster acquisition already decoded these bytes to validate them and discarded the result; the retaining path keeps it. It does so through `Codec` rather than `Image`, because `Image.makeFromEncoded` reports premultiplied alpha — it associates colour with alpha while decoding, so a red of 200 behind an alpha of 128 is stored as 100 and recovers only as 199. In a picture that rounding is invisible. In a DEM those channels are an elevation, so it silently moves the ground. ADR 0010 already forbade premultiplied alpha from leaking through the PNG boundary; the same rule governs this one, for a stronger reason.

The layout is fixed rather than inherited from the platform: red, green, blue, alpha byte order, rows top-down, tightly packed at `width * 4` bytes, and no colour-space conversion. Skia's N32 is BGRA on some of Rentile's targets and RGBA on others, so an N32-shaped buffer would decode one DEM to different elevations on different targets, and a destination naming a colour space would let a declared profile restate the channels. Elevation itself stays the consumer's arithmetic: these are packed channel values under the tile's own `TerrainDemEncoding`, never metres.

Retention is confined to callers that ask. Ordinary raster acquisition, hillshade rendering, substitution and the Output Tile path keep no decoded copy, so the memory cost falls on terrain consumers alone. Because one single-flight result is shared by every joiner, retention is part of the in-process dedupe identity rather than a property of whichever caller happened to create the flight; the alternative, retaining on every DEM fetch, would make each hillshade preparation decode and discard a megabyte per source tile. Terrain acquisition consequently performs a full decode where a lazily-decoded image previously parsed only a header, so a DEM with corrupt pixel data now fails at acquisition instead of later. Dimension and memory limits are still enforced from the header, before anything is allocated.

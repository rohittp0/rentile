# 0.17.0: explicit raster acquisition density

`RenderOptions` gains an appended `rasterAcquisitionDensity: RasterAcquisitionDensity` field.
Recompile consumers: source-compatible default arguments do not preserve the data class's
constructor/copy binary signatures.

The default `NATIVE` preserves 0.16.0: raster imagery source zoom is the output XYZ zoom plus
`log2(outputSizePx / declaredSourceTileSize)`, bounded by source limits. Existing default output
request/content keys remain unchanged. Hosts that want full source detail, including offline
exports, need no option change.

Choose `OUTPUT_ZOOM` to preserve 0.15.1's raster acquisition and output behavior, for example on
an interactive Preview that must retain its old decode and memory costs:

```kotlin
val previewOptions = RenderOptions(
    outputSizePx = 512,
    rasterAcquisitionDensity = RasterAcquisitionDensity.OUTPUT_ZOOM,
)
val exportOptions = RenderOptions(rasterAcquisitionDensity = RasterAcquisitionDensity.NATIVE)
```

Pass the same options to `warmRawResources` and `prepareBatch`. The original warming overload
uses default options and therefore remains `NATIVE`. Keep host LOD selection unchanged when
preserving legacy Preview behavior; this library option selects source imagery for the supplied
output XYZ and does not select that XYZ for the host.

`OUTPUT_ZOOM` selects `min(outputTile.z, source.maxZoom)`, ignores declared tile size for density,
and respects the output-zoom source minzoom and bounds as 0.15.1 did. Native output above source
maxzoom remains an ancestor crop. Identity PNG pass-through still requires payload dimensions
to match `outputSizePx`; other payload sizes are rendered to the requested size. Vector, DEM,
hillshade, labels and style zoom do not change. Raw source cache entries are reusable across both
modes; rendered output request/content keys are separate even when source coordinates coincide.

A style declaring 64-pixel tiles while returning 256-pixel payloads remains a catalogue metadata
issue. `NATIVE` honors the declaration; `OUTPUT_ZOOM` deliberately ignores tile size when choosing
source zoom. Neither mode rewrites metadata based on fetched payloads or invents detail above
source maxzoom.

Publication is complete only after the release workflow verifies all eight public coordinates
and a fresh consumer resolves the exact version from the public repository. Local publication
and compatibility evidence do not establish a public release.

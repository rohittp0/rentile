# Migrating from 0.11.x to 0.12.0

`0.12.0` is a deliberate breaking minor while Rentile is prerelease. The source tree declares
`VERSION_NAME=0.12.0`; that declaration requests the release but does not prove it has been
published. Upgrade only after `com.rohittp.rentile:kmp:0.12.0` resolves from
`https://maven.rohittp.com` and the release workflow has passed.

**Recompile every consumer.** `RentileConfiguration`, `LabelCandidate` and `LabelIconRef` each gain
fields appended to their constructors, so `0.11.x` binaries are not ABI-compatible with them. Every
other change is an addition.

The release is about a host that draws symbols itself:

- a second compatibility profile, `rentile-v1-host-symbols`, under which every symbol layer belongs
  to the host and an icon with no text is a Label Candidate of its own
  ([ADR 0035](../adr/0035-the-host-can-own-every-symbol-layer.md));
- each candidate's feature identity and its `text-size` and `icon-size` as functions of the camera's
  fractional zoom, reproducing Mapbox GL;
- a label-side `text-field` override, for a label-language setting that re-keys no Output Tile;
- the style's sprite sheet, at ratio 1 or the provider's `@2x`, through
  `acquireSpriteAtlas` ([ADR 0036](../adr/0036-hand-the-sprite-sheet-to-the-host.md));
- a glyph-atlas policy: pack only the glyphs the candidates draw, and cap the atlas's dimensions.

The two label-candidate keys move for everyone, because the candidate's public fields grew. Nothing
else moves under the defaults: with `CompatibilityPolicy.RentileV1`, `LabelCandidateOptions.Default`
and the default `LabelGlyphAtlasPolicy`, Output Tiles, raw pixels, `PreparedStyle.digest`,
`outputRequestKey`, `PreparedBatch.contentKeys`, style and batch diagnostics, label descriptors,
Glyph Closures, the glyph atlas and its key, and every pre-existing candidate field are what `0.11.4`
produced for identical inputs. The one exception is a style whose sprite sheet carries `stretchX`,
`stretchY` or `content` metadata, covered under [The sprite atlas](#the-sprite-atlas).

## What you have to do

1. Recompile. Wherever a test or fake constructs `LabelCandidate` or `LabelIconRef`, pass the new
   trailing arguments. Wherever a `when` over `DiagnosticCode` is exhaustive, add
   `SYMBOL_LAYER_HOST_OWNED` or an `else`. Code that constructs `RentileConfiguration` with named
   arguments compiles unchanged.
2. Discard label caches keyed by the `0.11.x` markers. Keep Output Tile caches and raw-resource
   caches.
3. To draw every symbol yourself, prepare with `CompatibilityPolicy.RentileV1HostSymbols` and treat a
   candidate with empty `glyphs` as an icon alone.
4. Draw icons from `acquireSpriteAtlas(style, pixelRatio = 2)`, looked up by
   `LabelIconRef.imageName`, instead of fetching and parsing the sprite yourself.
5. Scale glyphs, boxes and icons by `sizeAt(cameraZoom) / tileZoomSize` each frame.
6. De-duplicate line and polygon candidates across tiles by layer, `featureId` and `text`.
7. For a label-language setting, pass `LabelCandidateOptions` to `planLabelCandidates`,
   `acquireLabelCandidates` and `labelCandidateRequestKey` instead of rewriting the style.
8. For a GPU with a texture ceiling, configure
   `LabelGlyphAtlasPolicy(LabelGlyphPacking.REFERENCED_GLYPHS, maxDimensionPx = 4096)`.

### Source and binary compatibility

| Change | Effect on a consumer |
|---|---|
| `LabelCandidate` gains `featureId`, `text`, `textSize` at the end | Constructor, `copy` and `componentN` change (`component33` to `component35` are new). Code that constructs a candidate must pass them; code that only reads candidates compiles unchanged. |
| `LabelIconRef` gains `size` at the end | The same, for code constructing an icon reference (`component26` is new). |
| `RentileConfiguration` gains `labelGlyphAtlas` at the end, with a default | Constructor, `copy` and `component10` change in the JVM and klib ABI, so recompile, as `ValidatedDemTile` required in `0.7.0`. Named-argument construction compiles unchanged. |
| `DiagnosticCode.SYMBOL_LAYER_HOST_OWNED` | An exhaustive `when` over `DiagnosticCode` needs the branch or an `else`. Existing ordinals are unchanged. |
| Three `BasemapRasterizer` overloads taking `LabelCandidateOptions` | Each has a body in the interface, so a consumer's own `BasemapRasterizer` (a fake, a decorator) keeps compiling. That body serves `LabelCandidateOptions.Default` by delegating to the overload without options and throws `UnsupportedOperationException` for any override; a decorator that must pass overrides through overrides the new overloads. |
| `BasemapRasterizer.acquireSpriteAtlas` | Has a body that throws `UnsupportedOperationException`, so an existing implementation compiles unchanged and needs to override it only to fake sprite atlases. |
| `CompatibilityPolicy.RentileV1HostSymbols`, `LabelGlyphPacking`, `LabelGlyphAtlasPolicy`, `SymbolSizeKind`, `LabelSymbolSize`, `LabelCandidateOptions` and the four sprite types | Additive. `CompatibilityPolicy.Default` is still `RentileV1`. |

Every pre-existing field of `LabelCandidate`, `LabelIconRef` and `RentileConfiguration` keeps its
position, its meaning and, under the defaults, its value. `checkKotlinAbi` reports exactly these
changes against `0.11.4`: the only removed signatures are the old constructors and `copy` of those
three classes.

## Cache invalidation

| Identity | `0.11.x` | `0.12.0` | Action |
|---|---|---|---|
| Label candidate request key | `label-candidates-2` | `label-candidates-3` | Recompute every lookup key. |
| Label candidate batch content key | `rentile-label-candidates-2` | `rentile-label-candidates-3` | Discard cached candidate batches. |
| Either label key with a `text-field` override | - | gains a `text-field:` part | Nothing by hand: each language keys its own entries. |
| Either label key under `REFERENCED_GLYPHS` | - | gains `glyph-packing:referenced` | Nothing by hand: the two packings never share an entry. |
| Glyph atlas content key | unchanged | unchanged | Keep uploaded glyph textures. It moves with the texture under a cap or referenced packing, as it always has. |
| Output request and content keys | unchanged | unchanged | Keep Output Tile caches. |
| `PreparedStyle.digest` under `rentile-v1` | unchanged | unchanged | Keep identities derived from it. |
| Raw resources | unchanged | unchanged | Keep the raw cache. |

A `maxDimensionPx` cap changes neither label key: it moves cells, never indices. Every key derived
from a style prepared under `rentile-v1-host-symbols` differs from the same style's keys under
`rentile-v1`, because the profile id is part of `PreparedStyle.digest`.

## Behaviour under each profile

### `rentile-v1` (the default) - unchanged

Only the new fields are new, and the label keys move because of them. Under the default profile
`LabelCandidate.featureId`, `text` and `textSize`, and `LabelIconRef.size`, describe the same
candidates `0.11.4` produced.

### `rentile-v1-host-symbols` - opt-in

Prepare with `rasterizer.prepare(input, CompatibilityPolicy.RentileV1HostSymbols)`.

- **No symbol in Output Tiles.** No icon is drawn into a tile, no symbol layer requires the sprite,
  and a vector source only symbol layers read is never fetched for a tile. Patterns on background,
  fill and line layers are unaffected. Each visible symbol layer reports `SYMBOL_LAYER_HOST_OWNED`
  (INFO) with `labelLayer = true` when candidates represent it and `false` when nothing does - a
  symbol layer on a GeoJSON source, the one loss this profile accepts.
- **Every symbol layer with text or an icon is a label layer.** `labelLayerDescriptors` lists
  icon-only layers too.
- **Icon-only candidates.** A feature with an icon and no text yields a candidate whose `glyphs` are
  empty, whose `text` and `textSize` are null, whose `boundingBox` is `LabelBox(0, 0, 0, 0)` at the
  anchor and whose `textOptional` is true. Its placement, `line`, `rotationDegrees`,
  `symbolSpacing`, `avoidEdges`, `zOrder`, `sortKey`, `featureId` and `icon` are real. Its other
  text fields are inert constants - `overlap = ALWAYS`, `ignorePlacement = true`, `padding = 0`,
  `color`/`haloColor = 0`, `opacity = 0`, no halo, no translation, `keepUpright = false`,
  `textRotationDegrees = 0`, `maxAngleDegrees = 180`, `AUTO` alignments - so a host that forgets to
  skip them neither blocks, nor is blocked, nor draws. Place and collide the icon by its
  `LabelIconRef` fields. Its `textFit` is always `NONE`: with no text to fit to, Mapbox draws the
  icon at its sprite size, so the style's `icon-text-fit` does not apply.
- **A lost text keeps its icon.** A text-and-icon feature whose text evaluates empty, is in a script
  this profile cannot lay out, has an unusable text property, lays out to no glyphs, or belongs to a
  layer whose text construct the profile cannot compile yields its icon-only candidate.
  `LABEL_FEATURE_SKIPPED` gains the detail `textLostIconRetained` (present only under this profile)
  counting those; `COMPLEX_SCRIPT_LABEL_EXCLUDED` and `UNSUPPORTED_TEXT_CONSTRUCT` still report the
  text loss itself. A `text-size` of zero leaves the icon alone and reports nothing, as Mapbox draws
  it; an `icon-size` of zero on an icon-only feature leaves nothing and reports nothing.
- **No glyphs template.** Icon-only candidates are still planned and acquired; text-bearing features
  contribute their icons alone, and `GLYPH_RANGE_UNAVAILABLE` is on the plan and the batch.
- **No failure for a symbol's sake.** An unresolvable or undecodable sprite skips the icons
  (`ICON_FEATURE_SKIPPED`, `skippedMissingSprite`; an icon-only feature is also counted in
  `LABEL_FEATURE_SKIPPED.skippedFeatures`). An unresolvable source of any label layer, icon-only
  included, reports `LABEL_SOURCE_UNAVAILABLE` (legacy place-name layers stay strict, as before).
- **Text candidates are laid out exactly as under `rentile-v1`.** A text-and-icon candidate is
  equal across the two profiles.

Because every icon is a label icon under this profile, preparation resolves the sprite for any
style with a visible icon layer, so `acquireSpriteAtlas(style, 1)` hands back that prepared sheet.

## Candidate identity

`LabelCandidate.featureId` is the MVT feature id as its 64 bits (`featureId?.toULong()` recovers an
id above `Long.MAX_VALUE`), null when the feature declares none. `LabelCandidate.text` is the
evaluated text after `{token}` expansion, `text-transform` and trimming - the string the glyphs were
laid out from - and null for an icon-only candidate. With the layer
(`layerStyles[layerStyleIndex].layerId`) these identify one line or polygon feature anchored in
several tiles.

## Symbol size at the camera's fractional zoom

`LabelCandidate.textSize` and `LabelIconRef.size` are `LabelSymbolSize` values. `sizeAt(zoom)` is
the size Mapbox GL draws at fractional camera zoom `zoom`, reproducing Mapbox GL JS
`src/symbol/symbol_size.ts` and gl-native's `SymbolSizeBinder`: a zoom curve is interpolated between
its values at the stops covering `[z, z + 1]`, not evaluated at `zoom`, and the factor is clamped.
`tileZoomSize` is what every laid-out geometry used.

To draw at the camera size, with `k = size.sizeAt(cameraZoom) / size.tileZoomSize`:

```kotlin
// Glyphs: scale positions and scale; the text-padding margin of the box does not scale.
val quad = LabelGlyphQuad(q.entryIndex, q.x * k, q.y * k, q.scale * k)
val box = candidate.boundingBox.let { b -> val p = candidate.padding
    LabelBox((b.left + p) * k - p, (b.top + p) * k - p, (b.right - p) * k + p, (b.bottom - p) * k + p) }
// Icon: dimensions and icon-offset scale with icon-size; icon-translate does not.
val width = icon.width * kIcon; val height = icon.height * kIcon
val offsetX = icon.offsetX * kIcon; val offsetY = icon.offsetY * kIcon
```

`text-translate` and `icon-translate` never scale. Mapbox sizes collision boxes, and fits
`icon-text-fit` icons, from `text-size` evaluated exactly at `z + 1`; `sizeAt(z + 1.0)` equals it
for constant and source sizes and for a zoom curve with no stop strictly inside `(z, z + 1)`,
except a `step` or legacy `interval` curve with a stop at exactly `z + 1`. MapLibre GL JS changed
its camera sizing in August 2026 (#8175); these values follow Mapbox, not that change.

## The `text-field` override

`LabelCandidateOptions(textFieldOverride = json)` applies one `text-field` expression to every label
layer at acquisition. Travel Animator's label-language setting passes:

| Setting | `textFieldOverride` |
|---|---|
| Native | `["get","name"]` |
| English | `["coalesce",["get","name:en"],["get","name"]]` - English where the tiles have it, the local name where they omit `name:en` |

Any expression the profile can compile is accepted; construction throws `IllegalArgumentException`
for anything else. The override:

- changes no `PreparedStyle.digest`, no `outputRequestKey`, no `PreparedBatch.contentKeys` and no
  Output Tile - re-preparing the style with a rewritten `text-field` would have re-keyed every tile;
- joins `labelCandidateRequestKey(style, tiles, options)` and `LabelCandidateBatch.contentKey`, so
  caches for each language coexist; two spellings of one expression are one override;
- is compiled once per prepared style and override, on first use;
- under `rentile-v1-host-symbols`, gives an icon-only layer text, in the default font stack and size
  unless the layer declares its own, as setting `text-field` on it in Mapbox does;
- recompiles a layer whose own `text-field` the profile rejected, so a batch acquired with an
  override reports what compiling the override found instead of the prepare-time
  `UNSUPPORTED_TEXT_CONSTRUCT` for that layer.

A plan made with options carries them: `acquireLabelCandidates(plan)` applies the plan's override.
Under `REFERENCED_GLYPHS` an override's batch packs only the glyphs the overridden text draws.

## The sprite atlas

`BasemapRasterizer.acquireSpriteAtlas(style, pixelRatio = 1, resourceAccess = NORMAL): SpriteAtlas?`
returns the style's sprite sheet, so a consumer that draws icons itself never fetches or parses one
on its own. `SpriteAtlas` compares and hashes `pngBytes` by content, and `toString` prints a byte
count rather than the bytes.

- **`pixelRatio = 1`** returns the sheet the style was prepared with, without a request and
  whatever `resourceAccess` says. That is the sheet every `LabelIconRef.width` and `height` came
  from. A style that prepared without needing its sprite, because no layer draws an icon or a
  pattern, acquires the sheet on demand.
- **`pixelRatio = 2`** acquires `<sprite>@2x.json` and `<sprite>@2x.png`, with the suffix placed
  before any query, through the same raw store, revalidation and single flight. It is all-or-error
  and never falls back to the 1x sheet. Any other ratio throws `IllegalArgumentException`.
- **Access modes**: `CACHE_ONLY` never reaches the transport and schedules no background refresh.
  `RELOAD` fetches and replaces the stored entry. `CACHE_SUBSTITUTE_THEN_NETWORK` behaves as
  `NORMAL`.
- **null** means only that the style declares no `sprite`. An array-form (multi-sprite) `sprite`,
  or a relative one with no base URI, throws `StylePreparationException`.
- **Read each entry's own `pixelRatio`.** Do not assume it equals `SpriteAtlas.pixelRatio`. On
  2026-10-07, 7 of the 32 catalog styles that declare a sprite answered `@2x` with their 1x sheet.
- **Stretch and content metadata.** A sprite entry carrying `stretchX`, `stretchY` or `content` used
  to fail its whole sheet. Such metadata is now parsed, validated with MapLibre's rules (a bad value
  still fails the sheet) and exposed on `SpriteImageEntry`. The Output Tile path ignores it, which is
  exact: no icon on that path is resized by `icon-text-fit`, and a test proves the PNG is
  byte-identical with and without it. A style whose icon layer *required* such a sheet used to fail
  to prepare and now prepares. A style whose label layers only *desired* such a sheet now draws its
  repaired icons and emits its paired icons, where it used to lose them to
  `TEXT_COUPLED_ICON_LAYER_EXCLUDED` and `ICON_FEATURE_SKIPPED`. For exactly those styles the style
  digest changes, because it folds in the prepared sheet's content digest, and with it every output
  and label key; no marker moved. None of the 32 sprite-declaring catalog styles carries such
  metadata.

Cache an uploaded sheet under `SpriteAtlas.contentKey`. Nothing about a Label Candidate or its keys
depends on which sheet a host draws from.

### Drawing an icon from a sheet

Look up `atlas.entries[icon.imageName]` - for a paired icon and an icon-only candidate alike. Sample
its `x, y, width, height` rectangle of the decoded `pngBytes`. Draw it into a quad of
`icon.width * r` by `icon.height * r` device pixels, `r` being your device pixel ratio, after the
camera-zoom factor above. `LabelIconRef` sizes are style pixels at ratio one and already include
`icon-size` at the tile's zoom, so they do not change with the sheet. If a name is missing from the
`@2x` sheet, draw it from the 1x atlas.

`pngBytes` are the provider's bytes verbatim. Decode them to straight (unpremultiplied) RGBA. For
`sdf` entries, sample the alpha channel only: the signed distance lives there, with the edge at
`0.75` (`192/255`), as in MapLibre's SDF shader. The colour channels carry nothing, and they are
black in MapTiler's sheets. Rentile's glyph atlas uses the same alpha encoding with white colour
channels, so one alpha-only sampling rule serves both textures.

## Glyph-atlas packing and a texture cap

`RentileConfiguration.labelGlyphAtlas` lets a host bound the label glyph atlas it uploads to its
GPU. `LabelGlyphAtlasPolicy(packing, maxDimensionPx)` throws `IllegalArgumentException` for a
`maxDimensionPx` of zero or less.

- **Default**: nothing changes. `ACQUIRED_RANGES` packs every drawable glyph of every acquired Glyph
  Range, and its entries, atlas pixels and atlas key are what `0.11.4` produced.
  `LabelGlyphAtlasPolicyTest` pins the atlas key and its decoded pixels against `0.11.4`.
- **`REFERENCED_GLYPHS`** packs only the glyphs some candidate's quads reference, in the same
  canonical order. Labels are laid out against glyph metrics first, so the full atlas's pixel buffer
  is never allocated. Candidates are identical apart from `LabelGlyphQuad.entryIndex`, which indexes
  the shorter `LabelGlyphAtlas.entries`: the same quads, positions, scales, boxes and glyphs. An
  icon-only candidate has no quads and is untouched. Because the indices differ, both label keys
  gain `glyph-packing:referenced` under this packing, after any `text-field` part.
- **`maxDimensionPx`** caps the glyph atlas's width and height and nothing else. It lays the atlas
  out exactly as lowering `ResourceLimits.maxRasterDimensionPx` to the same value would, with the
  same texture and the same atlas key, but raster tiles and sprite sheets keep the full
  `maxRasterDimensionPx`. An atlas that cannot fit raises `SafetyLimitException` with `limitName`
  `labelGlyphAtlas.maxDimensionPx`. A batch with no text - an icon-only style under the host
  profile - packs nothing and cannot fail it.

For a GL host, use `LabelGlyphAtlasPolicy(LabelGlyphPacking.REFERENCED_GLYPHS, maxDimensionPx = 4096)`.
The cap alone does not fit dense CJK text: the default packing at 4096 overflows the cap's height,
as the table below shows.

## Release gates

The rolling-corpus gate renders every style under both profiles. `rentile-v1` is proved from the
committed Coverage Manifest as before. `rentile-v1-host-symbols` is proved from coverage **derived**
from that manifest rather than a second committed file: the independent point and line icon
capabilities take the `label-candidate` disposition, every visible vector symbol layer with text or
an icon needs a `LabelLayerDescriptor`, and the default profile's icon-repair diagnostics are
forbidden. The gate's label rows run the default glyph packing. See the
[corpus README](../../compatibility/README.md).

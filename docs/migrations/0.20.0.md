# 0.20.0: Material Coverage and color-relief layers

Two additive features. Existing styles, options and calls render the same pixels under the same
request and content keys as 0.19.0; no cached output needs discarding.

## Recompile

`RenderOptions` gains an appended `materialCoverage: MaterialCoverageRequest? = null`, and
`RenderedTile` and `RawRenderedTile` each gain an appended `materialCoverage: MaterialCoverage? =
null`. Default arguments keep Kotlin source compatible, but constructor, `copy` and `componentN`
binary signatures change, so recompile every consumer.

## Material Coverage

Tag the style layers that make up a material through their `metadata`, then request that pair:

```json
{"id": "water", "type": "fill", "source": "v", "source-layer": "water",
 "metadata": {"ta:material": "water"}, "paint": {"fill-color": "#9ec7f0"}}
```

```kotlin
val options = RenderOptions(
    outputSizePx = 512,
    materialCoverage = MaterialCoverageRequest(metadataKey = "ta:material", metadataValue = "water"),
)
val key = rasterizer.outputRequestKey(style, tile, options)        // differs from no request
rasterizer.prepareBatch(style, tiles, options).use { batch ->
    for (tile in rasterizer.renderRaw(batch).tiles) {              // or render(batch) for PNG
        when (val coverage = tile.materialCoverage) {
            is MaterialCoverage.Mask -> upload(tile.rgbaBytes, coverage.coverage) // 1 byte per pixel
            MaterialCoverage.None -> upload(tile.rgbaBytes, null)                  // nothing covered
            null -> error("not requested")
        }
    }
}
```

The mask is `outputSizePx` square, rows top-down, 0..255, aligned with the tile's pixels. It is the
material as it is **visible** in the finished tile: matching fill and line layers active at the
tile's zoom add their geometry (filters, widths, offsets, translates, dashes, caps, joins, blur and
antialiasing apply) at full strength whatever their colour, opacity or pattern, and later fill and
line layers that do not match - bridges, roads, piers, land patches - hide it in proportion to the
alpha they draw, so an opaque road over a river reads 0 and a 25%-opaque overlay reads 75%. Layers
before the first matching layer, and background, raster, hillshade, color-relief and icon layers,
never hide it. Background layers never contribute either: give the material explicit fill layers.
An empty (`204`) or out-of-bounds vector tile contributes nothing; a tile that fails to load fails
the render exactly as it does without a request. Store the mask beside the PNG or
pixels under the same request or content key: both keys include the request, and a tile cached
without one is not a tile with coverage. Warming needs no change, because coverage acquires nothing
extra. See [ADR 0042](../adr/0042-report-material-coverage-beside-the-output-tile.md).

## color-relief

Styles may now use MapLibre `color-relief` layers over a `raster-dem` source:

```json
{"id": "relief", "type": "color-relief", "source": "terrain",
 "paint": {"color-relief-opacity": 0.6,
           "color-relief-color": ["interpolate", ["linear"], ["elevation"],
                                  0, "#5a8f4e", 1000, "#c8b27a", 3000, "#ffffff"]}}
```

`color-relief-color` must be an `interpolate` (or `-hcl` / `-lab`) over `["elevation"]` with
strictly ascending stops; any other form fails preparation with `UNSUPPORTED_RETAINED_CONSTRUCT`
rather than drawing nothing as MapLibre GL does. `resampling` accepts `linear` (default) and
`nearest`. Such a style previously failed preparation outright, so nothing that rendered before
changes. `includeHillshade = false` does not omit color-relief layers. See
[ADR 0043](../adr/0043-draw-color-relief-layers-from-dem-elevations.md).

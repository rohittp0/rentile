# 0.19.0: observed native imagery detail metadata

`BasemapRasterizer` adds the default member:

```kotlin
fun rasterImageryDetailCeiling(
    style: PreparedStyle,
    options: RenderOptions = RenderOptions(),
): RasterImageryDetailCeiling?
```

No imagery returns null. Otherwise the report contains `maximumOutputZoom: Int?` and
`hasRasterizedVectorLayers: Boolean`. The maximum stays unknown until ordinary source acquisition
has validated payload dimensions for every imagery source. The query is network-free; it does not
render, warm or choose an output zoom. Raw warming alone does not validate payload dimensions.
Pass the same options as rendering because a source-zoom cap affects when source maxzoom is
reachable. The maximum also accounts for actual payload dimensions, which may disagree with the
declared tile size. Only a dimension is retained; no new image or raw-byte cache is introduced.

Preserve existing output zoom when other layers need finer vector, line or symbol paint. The
boolean reports vector layers actually retained in Output Tiles, excluding host-owned labels.
A coarser imagery-only output still evaluates raster paint at its requested tile zoom. The API
changes no rendering default, acquisition, output cache identity or pixel output. Existing
implementations inherit a conservative null result until they implement the report.

See [ADR 0041](../adr/0041-report-observed-native-imagery-detail.md) for the formula and observed
payload limitations. Public consumers should recompile against this additive minor release.

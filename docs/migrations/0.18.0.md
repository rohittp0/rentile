# 0.18.0: optional native raster source-zoom cap

`RenderOptions` gains an appended `maximumRasterSourceZoomDelta: Int? = null` field.
Recompile every consumer: default arguments preserve Kotlin source usage, not constructor/copy
binary signatures. Null preserves 0.17.0 native acquisition and existing output identities.

To bound native imagery's density-derived source zoom to at most one level above output XYZ:

```kotlin
val exportOptions = RenderOptions(
    outputSizePx = 512,
    rasterAcquisitionDensity = RasterAcquisitionDensity.NATIVE,
    maximumRasterSourceZoomDelta = 1,
)
```

Source maxzoom still applies. If this clamp falls below source minzoom, that raster source is
unavailable at this output; layer evaluation remains at the output zoom. The cap accepts 0..30,
never forces finer source acquisition and does not change declared tile sizes or payload handling.
Use identical options for `warmRawResources` and `prepareBatch`; explicit native caps have
separate output request/content identities. Raw source URL cache identities remain shareable.

`RasterAcquisitionDensity.OUTPUT_ZOOM` ignores this cap, including its keys and PNG output.
Interactive consumers preserving 0.15.1 behavior need no change. Vector, hillshade, DEM, layer
zoom and existing fallback/recovery policies are unaffected. See
[ADR 0040](../adr/0040-bound-native-raster-source-zoom-explicitly.md).

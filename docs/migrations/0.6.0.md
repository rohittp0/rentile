# Migrating from 0.5.x to 0.6.0

`0.6.0` is a deliberate breaking minor while Rentile is prerelease. The source tree declares
`VERSION_NAME=0.6.0`; that declaration requests the release but does not prove it has been
published. Upgrade only after `com.rohittp.rentile:kmp:0.6.0` resolves from
`https://maven.rohittp.com` and the release workflow has passed.

The release closes silent fidelity gaps in both label preparation and Output Tile rendering. It
changes public data classes instead of preserving compatibility aliases because the old types could
not faithfully represent line placement, cooperative collision, feature-driven paint, or a paired
icon. Recompile every consumer; `0.5.x` binaries are not ABI-compatible with these classes.

## Public API break ledger

### `LabelCandidate`

`LabelCandidate` changes its primary constructor, `copy`, destructuring components, equality, and
hash semantics.

| `0.5.x` | `0.6.0` | Consumer action |
|---|---|---|
| `allowOverlap: Boolean` | `overlap: SymbolOverlap` | Map `false` to `NEVER` and `true` to `ALWAYS`; handle `COOPERATIVE` as a distinct negotiation between colliding symbols. |
| Point anchor only | `placement: LabelPlacement` | Handle `POINT`, `LINE`, and `LINE_CENTER`. |
| No source-line geometry | `line: List<LabelLinePoint>` | Project this geographic line for line and line-center placement; it is empty for point placement. |
| No line tangent | `rotationDegrees: Double` | Use the selected source-line tangent as an orientation hint, then apply the consumer's camera/projection rules. |
| No repeat distance | `symbolSpacing: Double` | Use the style's pixel repeat distance when placing labels along a line. |
| No upright/edge/order intent | `keepUpright`, `avoidEdges`, `zOrder` | Apply these during viewport placement; `zOrder` preserves `AUTO`, `SOURCE`, and `VIEWPORT_Y`. |
| No complete text orientation contract | `textRotationDegrees`, `maxAngleDegrees`, `rotationAlignment`, `pitchAlignment` | Combine authored rotation with the line tangent and apply bend/alignment rules after projection. |
| No text/icon fallback intent | `textOptional` | Permit the paired icon to survive a text-placement failure only when this is true. |
| `LabelLayerStyle.color` | `LabelCandidate.color` | Read packed `0xAARRGGBB` text paint from each candidate because it may depend on the feature. |
| `LabelLayerStyle.haloColor` | `LabelCandidate.haloColor` | Read packed `0xAARRGGBB` halo paint from each candidate for the same reason. |
| Map-anchored text translation was assumed | `translateAlignment: SymbolAlignment` | Apply `text-translate` in the declared map or viewport frame. |

Twelve fields are inserted before `glyphs`, in this order: `placement`, `line`, `rotationDegrees`,
`symbolSpacing`, `keepUpright`, `avoidEdges`, `zOrder`, `textRotationDegrees`, `maxAngleDegrees`,
`rotationAlignment`, `pitchAlignment`, and `textOptional`. Later in the constructor,
`allowOverlap` is replaced by `overlap`, `color` and `haloColor` are inserted before the existing
opacity/halo scalars, and `translateAlignment` is appended after `translateY`. Code that constructs,
copies, destructures, serializes, or reflects over the data class must be updated even if it does not
draw line labels.

### `LabelLayerStyle`

`LabelLayerStyle` now contains only `layerId`, `zoom`, and `priority`. Its `color` and `haloColor`
properties are removed because newly admitted label layers can evaluate those properties per
feature. This changes its constructor, `copy`, destructuring components, equality, and hash
semantics. Read both colors from the selected `LabelCandidate` instead.

### `LabelIconRef`

`LabelIconRef` changes its primary constructor, `copy`, destructuring components, equality, and hash
semantics. The `0.5.x` `anchorOffsetX` and `anchorOffsetY` fields are removed. They were shifts
calculated from the sprite's original dimensions and could not remain correct after
`icon-text-fit` changed those dimensions. `0.6.0` instead inserts
`anchor: LabelIconAnchor` immediately after `width` and `height`; apply that anchor to the final,
possibly text-fitted icon box.

After the retained image, dimensions, offset, and translation fields, the constructor adds the
complete paired-icon inputs:

- `translateAlignment`
- `color`, `opacity`, `haloColor`, `haloWidth`, and `haloBlur`
- `rotationDegrees`
- `padding`, `optional`, `overlap`, and `ignorePlacement`
- `rotationAlignment`, `pitchAlignment`, `keepUpright`, and `avoidEdges`
- `textFit` and top/right/bottom/left `textFitPadding`

A consumer must apply paint and opacity, include the icon in collision according to its own
overlap/optional rules, resolve map-versus-viewport alignment after projection, and fit the icon to
the label's glyph bounds for `WIDTH`, `HEIGHT`, or `BOTH`. Resolve the fitted dimensions first, then
derive the declared `anchor` shift and add `offsetX`/`offsetY`. Rotate that combined icon-local
displacement by the icon's final rotation, then add `translateX`/`translateY` in the frame selected
by `translateAlignment`; translation does not rotate with the icon. Do not carry forward or
reconstruct the removed pre-fit shifts. Treat the icon and text as one symbol; drawing the icon
independently can violate both placement and collision semantics. Collision and edge avoidance must
use the final rotated icon box expanded by `padding`; use its axis-aligned envelope only for tile
edge checks or collision broad-phase checks. `haloWidth` and `haloBlur` affect paint, not collision
geometry.

`LabelIconRef` remains a reference, not a bitmap transport. As in `0.5.x`, the consumer resolves
sprite pixels and SDF/RGBA metadata from `imageName`; `LabelCandidateBatch` does not expose a public
sprite atlas. The break expands the geometry, paint, collision, alignment, and fit contract without
changing ownership of sprite imagery.

### New public value types

- `LabelPlacement`: `POINT`, `LINE`, `LINE_CENTER`
- `SymbolOverlap`: `NEVER`, `ALWAYS`, `COOPERATIVE`
- `SymbolAlignment`: `MAP`, `VIEWPORT`, `AUTO`
- `SymbolZOrder`: `AUTO`, `SOURCE`, `VIEWPORT_Y`
- `IconTextFit`: `NONE`, `WIDTH`, `HEIGHT`, `BOTH`
- `LabelIconAnchor`: `CENTER`, `LEFT`, `RIGHT`, `TOP`, `BOTTOM`, `TOP_LEFT`, `TOP_RIGHT`,
  `BOTTOM_LEFT`, `BOTTOM_RIGHT`
- `LabelLinePoint`: geographic `longitude` and `latitude`

These additions are not breaks by themselves, but they are now required by the changed data-class
constructors. Keep an `else` branch at external enum boundaries if a consumer must tolerate future
prerelease additions.

### `DiagnosticCode`

`LABEL_SOURCE_UNAVAILABLE` is added. It reports an INFO degradation when a non-place label source
newly admitted by 0.6.0 cannot be resolved or compiled. This is a source-compatibility break for an
exhaustive `when` over `DiagnosticCode`; add the new branch or an `else`. The pre-0.6 place-name
source set remains strict because those descriptors were already reachable behavior.

The existing `ICON_FEATURE_SKIPPED` WARNING also gains a second producer. Output Tile rendering
still reports it once per layer per tile; Label Candidate acquisition now reports it once per layer
per requested batch when a paired icon cannot compile or resolve. In that pipeline its counts span
the batch and `affectedTiles` identifies the contributing tiles. Consumers that interpreted those
counts as unconditionally single-tile must branch on the containing operation.

Several retained codes also change where or why they appear:

- `TEXT_ONLY_LAYER_EXCLUDED` and `TEXT_COMPONENT_REMOVED_ICON_RETAINED` describe only the Output
  Tile transformation. They can coexist with a Label Candidate Batch that contains that layer's
  text and paired icon.
- text-fitted icons no longer produce `TEXT_COUPLED_ICON_LAYER_EXCLUDED` merely because their
  geometry depends on text; the Label Candidate path carries their fit inputs.
- supported `line` and `line-center` placement no longer produces
  `LINE_PLACEMENT_LABEL_EXCLUDED`; that stable enum entry remains for old diagnostics and future
  failures classified the same way.
- `LABEL_FEATURE_SKIPPED.details["skippedNonPointGeometry"]` now counts empty, degenerate, or
  placement-incompatible geometry. It no longer means that all non-point geometry is unsupported.

## Label coverage and behavior changes

The `0.5.x` label closure admitted only place-name source layers. `0.6.0` admits every visible
text-bearing vector symbol layer exposed by the prepared style. That includes road,
point-of-interest, water, terrain, protected-area, and other style-authored text. Consequently:

- `labelLayerDescriptors` returns a broader, style-ordered list.
- `planLabelCandidates` and `acquireLabelCandidates` can acquire more Label Tiles and Glyph Ranges,
  return more candidates and layer styles, and reach resource limits sooner for the same viewport.
- `POINT` placement anchors point features directly, line features at their midpoint, and polygons
  at a deterministic hole-aware interior point. Multipart polygons can therefore emit one
  candidate per exterior instead of being discarded as non-point geometry.
- `LINE` and `LINE_CENTER` placement accept line geometry; each candidate carries the full
  geographic source line, tangent hint, and repeat spacing needed for viewport placement.
- text-bearing layers can return a paired icon, including icons whose size depends on text through
  `icon-text-fit`.
- a requested paired icon that cannot be emitted reports `ICON_FEATURE_SKIPPED` while retaining the
  text candidate; an unsupported icon construct no longer discards the enclosing text program.
  For Label Candidates this WARNING is emitted once per layer per requested batch, and its feature
  counts aggregate the tiles named by `affectedTiles`; it must not disappear without a diagnostic.

Consumers with exact-URL firewalls must preregister the complete `LabelCandidatePlan.glyphUrls`
closure rather than assuming place-name fan-out. The default `maxGlyphRangesPerBatch` increases
from 64 to 256: the expanded live corpus measured 159 ranges for Outdoor at Tokyo z14, whose
8192x4357 atlas uses 142,770,176 decoded bytes (136.16 MiB). A trial ceiling of 128 still failed
that valid plan. The new value is the next power of two above the measurement and remains bounded;
the independent `maxRasterDimensionPx` and `maxDecodedRasterBytes` ceilings still apply, so 256 is
not a guarantee that adversarial provider metrics fit. Consumers that copied the old default into
their own `ResourceLimits` must raise it explicitly or the newly reachable labels can still throw
`SafetyLimitException`. Review all resource limits under representative road/POI/CJK viewports.

Label layout properties are now evaluated with each feature rather than silently treated as one
layer-wide default where the style allows data-driven values. This includes placement and spacing,
anchor and `text-justify` (including `auto`), transform, padding, overlap/ignore-placement,
rotation and pitch alignment, rotation/max-angle, optionality, edge avoidance, translation
alignment, and z-order. Candidate counts, resolved values, and collision outcomes can therefore
differ from 0.5.x even when the layer itself was already discoverable.

## Expression and raster fidelity changes

The expression compiler now supports expression-form `!=`, `<`, `>`, `slice`, and `to-string`. These are the
strict comparisons and string/array slicing constructs that previously caused only the new text
program to degrade to `null`, leaving the style prepared but silently omitting labels. The legacy
filter forms remain supported. Supported occurrences no longer produce
`UNSUPPORTED_TEXT_CONSTRUCT` merely because they used one of these five operators.

Comparison typing is also stricter. Statically incompatible operands now fail compilation, and
`==`/`!=` accept only the style value categories for which equality is defined. A malformed
comparison that 0.5.x accepted permissively—or compiled only to evaluate as null—can now reject a
label text program with `UNSUPPORTED_TEXT_CONSTRUCT`, or fail a strict Output Tile/icon program.
Correctly typed comparison results are unchanged.

The line renderer now honors `line-round-limit`. Lines with round joins can therefore produce
different edge pixels from `0.5.x` for the same style, tile, and render options. Label restoration,
paired-icon handling, and the wider compiled expression set can also change diagnostics and
resource fan-out even when a consumer never used the old place-only label API.

Fixed-anchor symbol layers now honor literal or expression-valued `text-radial-offset`. A positive
radial offset replaces `text-offset` and moves the label outward from its declared `text-anchor`;
zero or a clamped-negative value retains the `text-offset` fallback. All nine fixed anchors are supported.
`text-variable-anchor` remains deliberately unsupported because selecting among candidate anchors
requires viewport collision state. Styles that previously lost these fixed-anchor text programs
with `UNSUPPORTED_TEXT_CONSTRUCT` can therefore emit labels at different positions in `0.6.0`.

Output Tile icons now evaluate functional `symbol-placement` (including `line-center`),
`icon-anchor`, `icon-padding`, overlap/ignore-placement, rotation and pitch alignment, translate
alignment, upright, edge-avoidance, and z-order properties per feature instead of silently
substituting their defaults. `cooperative` overlap and `symbol-z-order` are
applied during tile collision ordering: a cooperative candidate is blocked only by a colliding
previous `never` symbol, and `auto`/`viewport-y` ordering considers the collision intent of both the
icon and folded text halves. Rotated icons use oriented, padding-only collision geometry; their
anchor and offset rotate with the image while translation remains in its declared map/viewport
frame. Styles which depended on the old incorrect defaults can therefore produce different icon
positions, collision winners, and pixels.

## Cache invalidation

Do not reuse semantic caches created by `0.5.x`:

| Identity | `0.5.x` marker | `0.6.0` marker | Action |
|---|---|---|---|
| Label candidate request key | `label-candidates-1` | `label-candidates-2` | Recompute every lookup key before deciding whether to acquire. |
| Label candidate batch content key | `rentile-label-candidates-1` | `rentile-label-candidates-2` | Discard cached candidate batches/layout products. |
| Output request key | `rentile-output-request-1` | `rentile-output-request-2` | Recompute caller-owned PNG lookup keys. |
| Output content key | `rentile-output-2` | `rentile-output-3` | Discard PNGs indexed by the previous renderer semantics. |

The renderer semantic marker embedded in `PreparedStyle.digest` also changes from
`rentile-renderer-3` to `rentile-renderer-4`. The same style document therefore has a different
public digest after upgrading. Recompute every cache or registry identity derived from
`PreparedStyle.digest`; do not compare a `0.5.x` digest with a `0.6.0` digest as if they described
the same prepared semantics.

The Glyph Atlas shelf widens from 4096 to 8192 pixels so the raised range ceiling can fit the
measured dense closure. Identical glyph input that crossed the old shelf can therefore produce new
atlas dimensions, `LabelGlyphEntry` coordinates, PNG bytes, and `contentKey`; consumers must upload
the returned dimensions and must not assume a 4096-pixel maximum. No separate semantic marker is
needed because those derived bytes, dimensions, entries, and metrics already determine the content
key. Raw-resource caches remain reusable because their identities describe the original encoded
resources, not the derived atlas, candidate, or Output Tile semantics.

## Consumer migration sequence

1. Wait until the public `0.6.0` coordinate is verified; do not infer publication from this file or
   `gradle.properties`.
2. Change the dependency to `com.rohittp.rentile:kmp:0.6.0` and refresh dependencies.
3. Replace `allowOverlap` reads with an exhaustive `SymbolOverlap` policy.
4. Branch on `LabelPlacement`; project `line` and apply line spacing/orientation for both line modes.
   Apply `keepUpright`, `avoidEdges`, `zOrder`, and `translateAlignment` during viewport placement.
5. Move text `color` and `haloColor` reads from `LabelLayerStyle` to `LabelCandidate`.
6. Replace `anchorOffsetX/Y` handling with `LabelIconAnchor`, then fold `LabelIconRef` into the same
   placement/collision object as its text and implement its paint, alignment, optionality, and
   text-fit fields. Resolve `imageName` through the consumer-owned sprite resources; no public
   sprite atlas is added.
7. Invalidate old candidate and Output Tile cache entries and recompute identities derived from
   `PreparedStyle.digest`, as listed above. Do not invalidate the raw resource store solely for this
   upgrade.
8. Re-evaluate Glyph Range and candidate-count limits against the broader closure.
9. Compile and run the consumer on every published target, then compare representative label and
   line-rendering output before rollout.

A minimal collision migration looks like:

```kotlin
val permitsOverlap = when (candidate.overlap) {
    SymbolOverlap.NEVER -> false
    SymbolOverlap.ALWAYS -> true
    // A cooperative candidate is blocked only by an already placed NEVER symbol.
    SymbolOverlap.COOPERATIVE -> alreadyPlacedCollisions.all {
        it.overlap != SymbolOverlap.NEVER
    }
}

when (candidate.placement) {
    LabelPlacement.POINT -> placeAt(candidate.longitude, candidate.latitude)
    LabelPlacement.LINE,
    LabelPlacement.LINE_CENTER -> placeAlong(
        line = candidate.line,
        spacingPx = candidate.symbolSpacing,
        rotationHintDegrees = candidate.rotationDegrees,
    )
}
```

## Maintainer release checks

Before merging the non-documentation release commit:

```text
python3 tools/check_coverage_manifest.py compatibility/rentile-v1-coverage.json
python3 tools/check_corpus_fidelity_policy.py compatibility/rentile-v1-coverage.json
./gradlew :kmp:updateKotlinAbi
./gradlew :kmp:checkKotlinAbi
./gradlew :kmp:testAndroidHostTest :kmp:jvmTest :kmp:macosArm64Test
./gradlew :kmp:compileKotlinIosArm64 :kmp:compileKotlinIosSimulatorArm64
./gradlew :kmp:compileKotlinLinuxX64 :kmp:compileKotlinLinuxArm64
./gradlew :kmp:publishAllPublicationsToLocalTestRepository
./gradlew -p consumer-smoke -PrentileVersion=0.6.0 compileAndroidMain compileKotlinJvm compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinMacosArm64 compileKotlinLinuxX64 compileKotlinLinuxArm64
```

Inspect and accept both checked-in ABI dumps after `updateKotlinAbi`. The push to `main` starts the
publication workflow automatically; do not also manually dispatch it for the same commit. A release
is complete only after the workflow verifies every public artifact and resolves `0.6.0` from a fresh,
credential-free consumer.

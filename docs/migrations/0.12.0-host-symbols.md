# 0.12.0: host-owned symbols, candidate identity, symbol sizes and the text-field override

These are the label-side changes of `0.12.0`, to be merged into the release's `0.12.0.md`. They
change public data classes and add an enum entry, so every consumer recompiles; they discard label
caches but no Output Tile cache and no raw-resource cache. The default profile's Output Tiles are
byte-identical.

## Public API added

```kotlin
// A second compatibility profile; Default stays RentileV1.
CompatibilityPolicy.RentileV1HostSymbols            // id "rentile-v1-host-symbols", z0..z22

// Label-side options, with overloads that take them.
public data class LabelCandidateOptions(public val textFieldOverride: String? = null) {
    public companion object { public val Default: LabelCandidateOptions }
}
BasemapRasterizer.labelCandidateRequestKey(style, tiles, options: LabelCandidateOptions): String
BasemapRasterizer.planLabelCandidates(style, tiles, options: LabelCandidateOptions, resourceAccess = NORMAL)
BasemapRasterizer.acquireLabelCandidates(style, tiles, options: LabelCandidateOptions, resourceAccess = NORMAL)

// Symbol size as a function of camera zoom.
public enum class SymbolSizeKind { CONSTANT, SOURCE, CAMERA, COMPOSITE }
public data class LabelSymbolSize(
    kind: SymbolSizeKind, tileZoomSize: Double,
    lowerZoom: Double, upperZoom: Double, lowerSize: Double, upperSize: Double,
    interpolationBase: Double?,
) { public fun sizeAt(zoom: Double): Double }

// Appended at the end of existing constructors.
LabelCandidate(..., featureId: Long?, text: String?, textSize: LabelSymbolSize?)
LabelIconRef(..., size: LabelSymbolSize)

// Appended after every existing entry.
DiagnosticCode.SYMBOL_LAYER_HOST_OWNED
```

### Source and binary compatibility

| Change | Effect on a consumer |
|---|---|
| `LabelCandidate` gains `featureId`, `text`, `textSize` at the end | Constructor, `copy` and `componentN` change. Code that constructs a candidate (tests, fakes) must pass them; code that only reads candidates compiles unchanged. |
| `LabelIconRef` gains `size` at the end | Same, for code constructing an icon reference. |
| `DiagnosticCode.SYMBOL_LAYER_HOST_OWNED` | An exhaustive `when` over `DiagnosticCode` needs the branch or an `else`. Existing ordinals are unchanged. |
| Three `BasemapRasterizer` overloads taking `LabelCandidateOptions` | Each has a body in the interface, so a consumer's own `BasemapRasterizer` (a fake, a decorator) keeps compiling. That body serves `LabelCandidateOptions.Default` by delegating to the overload without options and throws `UnsupportedOperationException` for any override; a decorator that must pass overrides through overrides the new overloads. |
| `CompatibilityPolicy.RentileV1HostSymbols` | Additive. `CompatibilityPolicy.Default` is still `RentileV1`. |

Every pre-existing field of `LabelCandidate` and `LabelIconRef` keeps its position, meaning and,
under `RentileV1`, its value.

## Behaviour under each profile

### `rentile-v1` (the default) - unchanged

Output Tiles, raw pixels, `PreparedStyle.digest`, `outputRequestKey`, `PreparedBatch.contentKeys`,
style and batch diagnostics, label descriptors, glyph closures and every pre-existing candidate
field are byte-identical to `0.11.4` for identical inputs. Only the new fields are new, and the label
keys move because of them (below).

### `rentile-v1-host-symbols` - opt-in

Prepare with `rasterizer.prepare(input, CompatibilityPolicy.RentileV1HostSymbols)`.

- **No symbol in Output Tiles.** No icon is drawn into a tile, no symbol layer requires the sprite,
  and a vector source only symbol layers read is never fetched for a tile. Patterns on background,
  fill and line layers are unaffected. Each visible symbol layer reports `SYMBOL_LAYER_HOST_OWNED`
  (INFO) with `labelLayer = true` when candidates represent it and `false` when nothing does - a
  symbol layer on a GeoJSON source, the one loss this profile accepts.
- **Every symbol layer with text or an icon is a label layer.** `labelLayerDescriptors` lists
  icon-only layers too.
- **Icon-only candidates.** A feature with an icon and no text yields a candidate whose `glyphs` are
  empty, whose `text` and `textSize` are null, whose `boundingBox` is `LabelBox(0, 0, 0, 0)` at the
  anchor and whose `textOptional` is true. Its placement, `line`, `rotationDegrees`,
  `symbolSpacing`, `avoidEdges`, `zOrder`, `sortKey`, `featureId` and `icon` are real. Its other
  text fields are inert constants - `overlap = ALWAYS`, `ignorePlacement = true`, `padding = 0`,
  `color`/`haloColor = 0`, `opacity = 0`, no halo, no translation, `keepUpright = false`,
  `textRotationDegrees = 0`, `maxAngleDegrees = 180`, `AUTO` alignments - so a host that forgets to
  skip them neither blocks, nor is blocked, nor draws. Place and collide the icon by its
  `LabelIconRef` fields. Its `textFit` is always `NONE`: with no text to fit to, Mapbox draws the
  icon at its sprite size, so the style's `icon-text-fit` does not apply.
- **A lost text keeps its icon.** A text-and-icon feature whose text evaluates empty, is in a script
  this profile cannot lay out, has an unusable text property, lays out to no glyphs, or belongs to a
  layer whose text construct the profile cannot compile yields its icon-only candidate.
  `LABEL_FEATURE_SKIPPED` gains the detail `textLostIconRetained` (present only under this profile)
  counting those; `COMPLEX_SCRIPT_LABEL_EXCLUDED` and `UNSUPPORTED_TEXT_CONSTRUCT` still report the
  text loss itself. A `text-size` of zero leaves the icon alone and reports nothing, as Mapbox draws
  it; an `icon-size` of zero on an icon-only feature leaves nothing and reports nothing.
- **No glyphs template.** Icon-only candidates are still planned and acquired; text-bearing features
  contribute their icons alone, and `GLYPH_RANGE_UNAVAILABLE` is on the plan and the batch.
- **No failure for a symbol's sake.** An unresolvable or undecodable sprite skips the icons
  (`ICON_FEATURE_SKIPPED`, `skippedMissingSprite`; an icon-only feature is also counted in
  `LABEL_FEATURE_SKIPPED.skippedFeatures`). An unresolvable source of any label layer, icon-only
  included, reports `LABEL_SOURCE_UNAVAILABLE` (legacy place-name layers stay strict, as before).
- **Text candidates are laid out exactly as under `rentile-v1`.** A text-and-icon candidate is
  equal across the two profiles.

Every key derived from a style prepared under this profile differs from the same style's keys under
`rentile-v1`, because the profile id is part of `PreparedStyle.digest`.

## Candidate identity

`LabelCandidate.featureId` is the MVT feature id as its 64 bits (`featureId?.toULong()` recovers an
id above `Long.MAX_VALUE`), null when the feature declares none. `LabelCandidate.text` is the
evaluated text after `{token}` expansion, `text-transform` and trimming - the string the glyphs were
laid out from - and null for an icon-only candidate. With the layer
(`layerStyles[layerStyleIndex].layerId`) these identify one line or polygon feature anchored in
several tiles.

## Symbol size at the camera's fractional zoom

`LabelCandidate.textSize` and `LabelIconRef.size` are `LabelSymbolSize` values. `sizeAt(zoom)` is
the size Mapbox GL draws at fractional camera zoom `zoom`, reproducing Mapbox GL JS
`src/symbol/symbol_size.ts` and gl-native's `SymbolSizeBinder`: a zoom curve is interpolated between
its values at the stops covering `[z, z + 1]`, not evaluated at `zoom`, and the factor is clamped.
`tileZoomSize` is what every laid-out geometry used.

To draw at the camera size, with `k = size.sizeAt(cameraZoom) / size.tileZoomSize`:

```kotlin
// Glyphs: scale positions and scale; the text-padding margin of the box does not scale.
val quad = LabelGlyphQuad(q.entryIndex, q.x * k, q.y * k, q.scale * k)
val box = candidate.boundingBox.let { b -> val p = candidate.padding
    LabelBox((b.left + p) * k - p, (b.top + p) * k - p, (b.right - p) * k + p, (b.bottom - p) * k + p) }
// Icon: dimensions and icon-offset scale with icon-size; icon-translate does not.
val width = icon.width * kIcon; val height = icon.height * kIcon
val offsetX = icon.offsetX * kIcon; val offsetY = icon.offsetY * kIcon
```

`text-translate` and `icon-translate` never scale. Mapbox sizes collision boxes, and fits
`icon-text-fit` icons, from `text-size` evaluated exactly at `z + 1`; `sizeAt(z + 1.0)` equals it
for constant and source sizes and for a zoom curve with no stop strictly inside `(z, z + 1)`,
except a `step` or legacy `interval` curve with a stop at exactly `z + 1`. MapLibre GL JS changed its camera sizing in August 2026
(#8175); these values follow Mapbox, not that change.

## The `text-field` override

`LabelCandidateOptions(textFieldOverride = json)` applies one `text-field` expression to every label
layer at acquisition. Travel Animator's label-language setting passes:

| Setting | `textFieldOverride` |
|---|---|
| Native | `["get","name"]` |
| English | `["coalesce",["get","name:en"],["get","name"]]` - English where the tiles have it, the local name where they omit `name:en` |

Any expression the profile can compile is accepted; construction throws `IllegalArgumentException`
for anything else. The override:

- changes no `PreparedStyle.digest`, no `outputRequestKey`, no `PreparedBatch.contentKeys` and no
  Output Tile - re-preparing the style with a rewritten `text-field` would have re-keyed every tile;
- joins `labelCandidateRequestKey(style, tiles, options)` and `LabelCandidateBatch.contentKey`, so
  caches for each language coexist; two spellings of one expression are one override;
- is compiled once per prepared style and override, on first use;
- under `rentile-v1-host-symbols`, gives an icon-only layer text, in the default font stack and size
  unless the layer declares its own, as setting `text-field` on it in Mapbox does;
- recompiles a layer whose own `text-field` the profile rejected, so a batch acquired with an
  override reports what compiling the override found instead of the prepare-time
  `UNSUPPORTED_TEXT_CONSTRUCT` for that layer.

A plan made with options carries them: `acquireLabelCandidates(plan)` applies the plan's override.

## Cache invalidation

| Identity | `0.11.x` marker | `0.12.0` marker | Action |
|---|---|---|---|
| Label candidate request key | `label-candidates-2` | `label-candidates-3` | Recompute every lookup key. |
| Label candidate batch content key | `rentile-label-candidates-2` | `rentile-label-candidates-3` | Discard cached candidate batches. |
| Output request and content keys | unchanged | unchanged | Keep Output Tile caches. |
| `PreparedStyle.digest` under `rentile-v1` | unchanged | unchanged | Keep identities derived from it. |

The glyph atlas content key is unchanged, since glyph pixels are. Raw-resource caches stay valid.

## Consumer migration sequence

1. Recompile; add the three new constructor arguments wherever a test or fake constructs
   `LabelCandidate` or `LabelIconRef`, and an `else` or `SYMBOL_LAYER_HOST_OWNED` branch wherever a
   `when` over `DiagnosticCode` is exhaustive.
2. Discard label caches keyed by the old markers. Keep Output Tile and raw caches.
3. To draw every symbol yourself, prepare with `CompatibilityPolicy.RentileV1HostSymbols`, treat a
   candidate with empty `glyphs` as an icon alone, and resolve icon imagery by
   `LabelIconRef.imageName` from the style's sprite, as before.
4. Scale glyphs, boxes and icons by `sizeAt(cameraZoom) / tileZoomSize` each frame.
5. De-duplicate line and polygon candidates across tiles by layer, `featureId` and `text`.
6. For a label-language setting, pass `LabelCandidateOptions` to `planLabelCandidates`,
   `acquireLabelCandidates` and `labelCandidateRequestKey` instead of rewriting the style.

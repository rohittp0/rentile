# 0.15.0: progressive hillshade and bounded CPU sampling

`RenderOptions.includeHillshade` defaults to `true`. Existing full-detail output request and
content keys remain unchanged. A host may pass `false` for temporary map coverage: these batches
omit hillshade draw layers and their DEM acquisition, and use separate output keys. The prepared
style remains unchanged, so later full-detail batches and terrain acquisition still work normally.
Use this option only where the host can replace temporary coverage with full-detail output.

The added data-class parameter changes JVM/klib constructor and copy signatures. Recompile hosts
against 0.15.0; do not replace the library binary beneath an already compiled host.

Hillshade now copies each decoded DEM's canonical RGBA once, caches a bounded gradient height
window per draw and reuses identical nearest-neighbour output samples. Shading equations,
coordinate mapping and full-detail cache identity are unchanged. Tests pin Skia N32 colour
rounding for both DEM encodings, including every alpha value, non-square images and clamped
edges, plus repeated samples and cross-tile gradients. The patch is based on 0.14.0 and retains
its empty-DEM and host-scenery behaviour.

Verification before publication: full Android host and iOS 26.0 simulator suites, JVM/klib ABI
checks, and local Maven consumption by Travel Animator on Samsung SM-G990B2. Device timings and
consumer scheduling policy are recorded in Travel Animator's 2026-10-12 elevation investigation.
Publication is complete only after the release workflow verifies all eight public coordinates.

# 0.12.0: sprite atlas and glyph-atlas packing

This fragment holds the 0.12.0 changes for two atlases. The release task merges it into
`0.12.0.md`. Both changes are opt-in. A consumer that calls neither new API keeps every output and
label key, every Output Tile pixel and every Label Candidate exactly as in `0.11.4`. The one
exception is a style whose sprite sheet carries `stretchX`, `stretchY` or `content` metadata,
covered under "Behaviour".

## Public sprite atlas (ADR 0036)

`BasemapRasterizer.acquireSpriteAtlas(style, pixelRatio = 1, resourceAccess = NORMAL): SpriteAtlas?`
returns the style's sprite sheet, so a consumer that draws icons itself never fetches or parses one
on its own. See [ADR 0036](../adr/0036-hand-the-sprite-sheet-to-the-host.md).

### New public types

- `SpriteAtlas(pngBytes, width, height, pixelRatio: Int, contentKey, entries: Map<String, SpriteImageEntry>)`.
  It compares and hashes `pngBytes` by content, and `toString` prints a byte count rather than the
  bytes.
- `SpriteImageEntry(name, x, y, width, height, pixelRatio: Double, sdf, stretchX, stretchY, content)`
- `SpriteStretchRange(from, to)` and `SpriteContentBox(left, top, right, bottom)`

### `BasemapRasterizer` gains a member

`acquireSpriteAtlas` has a default body that throws `UnsupportedOperationException`. A consumer's
own `BasemapRasterizer` implementation, such as a test fake, compiles unchanged and needs to
override it only to fake sprite atlases.

### Behaviour

- **`pixelRatio = 1`** returns the sheet the style was prepared with, without a request and
  whatever `resourceAccess` says. That is the sheet every `LabelIconRef.width` and `height` came
  from. A style that prepared without needing its sprite, because no layer draws an icon or a
  pattern, acquires the sheet on demand.
- **`pixelRatio = 2`** acquires `<sprite>@2x.json` and `<sprite>@2x.png`, with the suffix placed
  before any query, through the same raw store, revalidation and single flight. It is all-or-error
  and never falls back to the 1x sheet. Any other ratio throws `IllegalArgumentException`.
- **Access modes**: `CACHE_ONLY` never reaches the transport and schedules no background refresh.
  `RELOAD` fetches and replaces the stored entry. `CACHE_SUBSTITUTE_THEN_NETWORK` behaves as
  `NORMAL`.
- **null** means only that the style declares no `sprite`. An array-form (multi-sprite) `sprite`,
  or a relative one with no base URI, throws `StylePreparationException`.
- **Read each entry's own `pixelRatio`.** Do not assume it equals `SpriteAtlas.pixelRatio`. On
  2026-10-07, 7 of the 32 catalog styles that declare a sprite answered `@2x` with their 1x sheet.
- **Stretch and content metadata.** A sprite entry carrying `stretchX`, `stretchY` or `content` used
  to fail its whole sheet. Such metadata is now parsed, validated with MapLibre's rules (a bad value
  still fails the sheet) and exposed on `SpriteImageEntry`. The Output Tile path ignores it, which is
  exact: no icon on that path is resized by `icon-text-fit`, and a test proves the PNG is
  byte-identical with and without it. A style whose icon layer *required* such a sheet used to fail
  to prepare and now prepares. A style whose label layers only *desired* such a sheet now draws its
  repaired icons and emits its paired icons, where it used to lose them to
  `TEXT_COUPLED_ICON_LAYER_EXCLUDED` and `ICON_FEATURE_SKIPPED`. For exactly those styles, the style
  digest changes, because it folds in the prepared sheet's content digest, and with it every output
  and label key. No marker moved. None of the 32 sprite-declaring catalog styles carries such
  metadata.

### Drawing a paired icon from a sheet

Look up `atlas.entries[icon.imageName]`. Sample its `x, y, width, height` rectangle of the decoded
`pngBytes`. Draw it into a quad of `icon.width * r` by `icon.height * r` device pixels, `r` being
your device pixel ratio. `LabelIconRef` sizes are style pixels at ratio one and already include
`icon-size`, so they do not change with the sheet. If a name is missing from the `@2x` sheet, draw
it from the 1x atlas.

`pngBytes` are the provider's bytes verbatim. Decode them to straight (unpremultiplied) RGBA. For
`sdf` entries, sample the alpha channel only: the signed distance lives there, with the edge at
`0.75` (`192/255`), as in MapLibre's SDF shader. The colour channels carry nothing, and they are
black in MapTiler's sheets. Rentile's glyph atlas uses the same alpha encoding with white colour
channels, so one alpha-only sampling rule serves both textures.

### What to discard

Nothing. No marker changed. Cache an uploaded sheet under `SpriteAtlas.contentKey`.

## Glyph-atlas packing and a texture cap

`RentileConfiguration` gains `labelGlyphAtlas: LabelGlyphAtlasPolicy = LabelGlyphAtlasPolicy()`,
which lets a host bound the label glyph atlas it uploads to its GPU.

### New public types

- `LabelGlyphPacking`: `ACQUIRED_RANGES`, the default and what every earlier release packed, and
  `REFERENCED_GLYPHS`.
- `LabelGlyphAtlasPolicy(packing = ACQUIRED_RANGES, maxDimensionPx: Int? = null)`. A
  `maxDimensionPx` of zero or less throws `IllegalArgumentException`.

### `RentileConfiguration` changes shape

The field is appended to the end of the constructor, so code that names its arguments compiles
unchanged. The constructor, `copy` and `component10` change in the JVM and klib ABI, so recompile
against 0.12.0, as `ValidatedDemTile` required in 0.7.0.

### Behaviour

- **Default**: nothing changes. The default packs every drawable glyph of every acquired Glyph
  Range, and its entries, atlas pixels, atlas key, candidates, request key and content key are what
  0.11.4 produced. `LabelGlyphAtlasPolicyTest` pins the atlas key and its decoded pixels against
  0.11.4. The request key, content key and candidates were compared for equality before and after
  this change.
- **`REFERENCED_GLYPHS`** packs only the glyphs some candidate's quads reference, in the same
  canonical order. Labels are laid out against glyph metrics first, so the full atlas's pixel buffer
  is never allocated. Candidates are identical apart from `LabelGlyphQuad.entryIndex`, which indexes
  the shorter `LabelGlyphAtlas.entries`: the same quads, positions, scales, boxes and glyphs. Because
  the indices differ, `labelCandidateRequestKey` and `LabelCandidateBatch.contentKey` gain a
  `glyph-packing:referenced` component under this packing, so a cache filled under one packing never
  serves the other.
- **`maxDimensionPx`** caps the glyph atlas's width and height and nothing else. It lays the atlas
  out exactly as lowering `ResourceLimits.maxRasterDimensionPx` to the same value would, with the
  same texture and the same atlas key, but raster tiles and sprite sheets keep the full
  `maxRasterDimensionPx`. An atlas that cannot fit raises `SafetyLimitException` with `limitName`
  `labelGlyphAtlas.maxDimensionPx`. A cap moves cells, never indices, so it changes neither label
  key. The atlas key covers the atlas dimensions and moves with the texture.

For a GL host, use `LabelGlyphAtlasPolicy(LabelGlyphPacking.REFERENCED_GLYPHS, maxDimensionPx = 4096)`.
The cap alone does not fit dense CJK text: the default packing at 4096 overflows the cap's height,
as the table below shows.

### Measured footprint

`GlyphAtlasFootprintProbe` (`RENTILE_GLYPH_ATLAS_PROBE_DIR=<dir>`, `:kmp:testAndroidHostTest`).
Decoded bytes are `width * height * 4`, which is what an RGBA8888 upload costs. The 3x3 cases are
the z14 tile and its eight neighbours, the shape of a real viewport.

The Tokyo z14 default row reproduces the corpus README's measurement from 2026-08-23 exactly. For
CJK, referenced packing cuts the atlas 73x for one tile and 38x for a 3x3 viewport. That viewport's
default atlas, at 214.9 MiB, sits within 41 MiB of the 256 MiB `maxDecodedRasterBytes` default. For
Latin text the uncapped cut is about 7x. Under a 4096 cap a referenced Latin atlas can occupy more area than
an uncapped one, because the last shelf is cut at the cap's width. It is still well under 1 MiB.

### What to discard

Nothing, under the default. A host that switches to `REFERENCED_GLYPHS` gets new label keys by
itself and needs to discard nothing by hand.

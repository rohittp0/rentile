# Migrating from 0.11.3 to 0.11.4

`0.11.4` is a fix release. It changes no public type, no signature, no key and no pixel:
`checkKotlinAbi` reports no JVM or klib change, so it is a drop-in replacement for `0.11.3` with no
recompile and no cache to discard.

## What changed

One thing a consumer can observe: **a style that `0.11.3` refused now prepares.** A `filter` on a
`raster`, `hillshade` or `background` layer is accepted and ignored instead of failing the whole style
with `UNSUPPORTED_RETAINED_CONSTRUCT`.

Those layers have no features to filter, and the MapLibre style schema does not define `filter` for
them, so the property cannot change a pixel. Real styles carry it anyway: a Satellite style served
to Travel Animator has `"filter":["all"]` on its single raster layer, and under `0.11.3` its preview
drew an error instead of a map and its video export aborted. The leniency covers any filter
expression on those three layer types, not only the no-op `["all"]`, because a filter says nothing
on a featureless layer whatever it contains. A construct that can alter drawing still fails loudly.

## What you have to do

Nothing. A style that prepared under `0.11.3` prepares to the same `PreparedStyle.digest`, the same
Output Tile keys and the same pixels. A consumer that treated the old `StylePreparationException`
for such a style as permanent - a cached "unsupported style" verdict, say - should retry it.

## Release completeness

**`0.11.4` is whole.** All eight coordinates - `kmp`, `kmp-android`, `kmp-jvm`, `kmp-iosarm64`,
`kmp-iossimulatorarm64`, `kmp-macosarm64`, `kmp-linuxx64` and `kmp-linuxarm64` - serve a `0.11.4`
`.pom` and its `.asc` signature from `https://maven.rohittp.com`, every coordinate's
`maven-metadata.xml` names `<release>0.11.4</release>`, and every metadata document matches its
published `md5` and `sha1`. Checked from outside CI on 2026-10-08.

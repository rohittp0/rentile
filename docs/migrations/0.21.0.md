# 0.21.0: style metadata descriptor

Additive. `BasemapRasterizer` gains `styleMetadataDescriptor(style: PreparedStyle):
StyleMetadataDescriptor`, with two new data classes. Nothing existing changes: no signature, key,
pixel or corpus output moves, and nothing is computed unless the member is called. Implementations
other than Rentile's inherit a default that throws `UnsupportedOperationException`.

```kotlin
val style = rasterizer.prepare(StyleInput.Remote(styleUrl))
val metadata = rasterizer.styleMetadataDescriptor(style)

metadata.rootMetadataJson                 // e.g. {"ta:look":"glossy"}, or null
for (layer in metadata.layers) {          // drawn layers declaring metadata, in style order
    layer.id; layer.styleLayerIndex; layer.type; layer.metadataJson
    layer.minimumZoom; layer.maximumZoom; layer.materialCoverageEligible
}
```

Values are JSON text in the author's key order; parse them with your own JSON library. String
values have authentication query values redacted as in the style digest.

To decide whether a Material Coverage request for key `K` and string value `V` can be non-empty at
output zoom `z`, look for a layer with `materialCoverageEligible`, `minimumZoom <= z < maximumZoom`
and a metadata object mapping `K` to `V`. If none exists, coverage is `None` at that zoom without
rendering. If one exists, coverage can still be `None` (no geometry in the tile, or later layers
hide it). Only layers drawn into the Output Tile are listed: hidden, excluded, Label and
host-owned extrusion layers never are, and background, raster, hillshade, color-relief and icon
layers are listed but never eligible. See
[ADR 0044](../adr/0044-describe-style-metadata-for-hosts.md).

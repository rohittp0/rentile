Kotlin Multiplatform · CPU rasterization

Map styles in.

Rentile is a headless basemap renderer for background work. Give it a supported style and XYZ coordinates; receive deterministic PNG bytes without a view, display server, graphics context, or SDK-owned render loop.

One dependency

A platform-neutral boundary

Consumers depend on one coordinate from common code. Platform-specific artifacts are selected by Gradle metadata.

Skiko platform artifacts currently resolve from JetBrains' public Compose repository. Add the narrow org.jetbrains.skiko repository filter shown in the KMP reference before declaring Rentile.
build.gradle.kts development 
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation(
                "com.rohittp.rentile:kmp:0.1.0-SNAPSHOT"
            )
        }
    }
}

Rendering profile

Focused on basemaps, not map UI

01

Strict style preparation

Reachable expressions, filters, sources, sprites, and compatibility transformations are validated before tile drawing starts.

02

Vector and raster sources

Vector, raster, DEM, sprite, and selected GeoJSON resources share one deterministic resource-planning boundary.

03

Always encoded PNG

PNG, JPEG, and WebP raster inputs are accepted where supported. Every successful public tile result is PNG.

04

Caller-owned orchestration

The caller owns priority, batching, output caching, retry, and fallback. Rentile owns cancellable bounded work and diagnostics.

Public contract

Prepared once.
Rendered without network.

Preparation freezes every byte needed by a caller-defined tile set. Drawing then operates against immutable resources and exposes content keys before rasterization, so the caller can consult its own output cache first.

Common Kotlincontract
val rasterizer = Rentile.create(config)

rasterizer.use { renderer ->
    val style = renderer.prepare(styleInput)
    renderer.prepareBatch(style, tiles).use { batch ->
        // Network and store access are complete.
        val keys = batch.contentKeys
        val result = renderer.render(batch)
        consume(result.tiles) // PNG ByteArrays
    }
}

Deliberate boundaries

Clear ownership keeps the module deep

Rentile owns

  • Style compilation and diagnostics
  • Resource closure and raw-resource caching
  • Bounded scheduling and single-flight work
  • CPU drawing and PNG encoding
  • Stable content identities

The caller owns

  • Batch construction and priority
  • Output PNG caching
  • Retry, fallback, and recovery
  • API keys and transport implementation
  • Plane, globe, overlays, and presentation

KMP reference

The platform-neutral contract for preparing supported map styles and rendering north-up XYZ basemap tiles into encoded PNG bytes.

0.1.0-SNAPSHOT Apache-2.0 Versioned profile
Preimplementation contract. API names shown here reflect the approved design and may be refined before the first local artifact. Behavioral guarantees are normative once implemented.

Installation

Add the common dependency

During development, resolve the snapshot from the local Maven repository used by the clean-consumer tests.

settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        mavenLocal()
        mavenCentral()
        google()
    }
}
build.gradle.kts
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("com.rohittp.rentile:kmp:0.1.0-SNAPSHOT")
        }
    }
}
The first Maven Central version is 0.1.0. Snapshot versions are never uploaded to Central.

Compatibility

A pinned compatibility profile

Rentile intentionally implements a pinned basemap profile rather than arbitrary future MapLibre Style Specification behavior. Preparation fails when a retained layer reaches unsupported syntax.

Included

  • Background, fill, line, raster, and hillshade
  • Sprite-backed fill, line, and background patterns
  • Approved independent RGBA and SDF icons
  • Flattened top-down building footprints
  • Vector, raster, DEM, sprite, TileJSON, and selected GeoJSON resources

Excluded

  • Text rendering, glyphs, fonts, shaping, and bidi
  • Text-coupled icons
  • Fog, sky, snow, root terrain, and globe presentation
  • Perspective extrusion and UI camera state
  • Feature state, fades, and wall-clock animation

API

Prepare, inspect, render

The split API exposes deterministic output content keys after all resource access completes but before drawing. A convenience method may compose the stages without changing their semantics.

Contract sketch
interface BasemapRasterizer : AutoCloseable {
    suspend fun prepare(
        style: StyleInput,
        policy: CompatibilityPolicy = CompatibilityPolicy.Default,
    ): PreparedStyle

    suspend fun prepareBatch(
        style: PreparedStyle,
        tiles: List<TileId>,
        options: RenderOptions = RenderOptions(),
        resourceAccess: ResourceAccess = ResourceAccess.NORMAL,
    ): PreparedBatch

    suspend fun render(
        batch: PreparedBatch,
        tiles: List<TileId> = batch.tiles,
    ): RenderBatch

    suspend fun awaitClosed()
}

Output boundary

Rendered tile
data class RenderedTile(
    val id: TileId,
    val pngBytes: ByteArray,
    val contentKey: String,
    val diagnostics: List<RenderDiagnostic>,
)

Every successful tile is canonical RGBA8 sRGB PNG. PNG byte streams are not promised to match across platforms; decoded pixels follow the versioned tolerance contract.

I/O boundary

Host-provided transport

Rentile does not export Ktor, OkHttp, Darwin, CIO, or Curl through its public surface. The host implements a bounded request/response exchange using Rentile's project-owned models. Rentile owns URL canonicalization, redirect policy, resource planning, session decoration, cache identity, and redacted metrics.

Credentials

Provider credentials may already be present in the style JSON. Rentile detects those first. The caller supplies credentials separately only when a required resource lacks them. Keys and session identifiers never enter logs, diagnostics, file paths, or content identities.

Credentials are attached only to exact configured HTTPS origins and are removed on origin-changing redirects.

Caching

Raw resources in Rentile, output tiles in the caller

Rentile

  • Persistent encoded raw resources
  • Bounded in-memory compiled styles
  • Bounded in-memory decoded sources
  • In-process single-flight work

Caller

  • Rendered PNG storage
  • Output eviction policy
  • Cross-process output coordination
  • Fallback rendered-tile namespaces

A failed tile never rolls back successful raw-resource cache entries acquired for other work. Partial or corrupt entries are never committed.

Failures

Typed errors, caller-owned recovery

Rentile reports full, redacted diagnostics through custom exception families. It does not retry, refetch, substitute, fall back, or return partial tile batches. The caller decides whether to retry, cancel, or choose another renderer.

StylePreparationException ResourceAcquisitionException ResourceDecodeException RasterizationException PngEncodingException ResourceStoreException SafetyLimitException PreparedBatchClosedException

CancellationException is never wrapped. The first terminal failure cancels only work owned by that call; shared work continues while another waiter remains.

Lifecycle

Common Kotlin closeables

BasemapRasterizer and PreparedBatch implement common AutoCloseable. Closing is idempotent, non-blocking, and non-throwing. It prevents new operations while active leases finish safely. Call awaitClosed() when complete native cleanup must be observed.

Jobs are cancellable; the caller controls priority by deciding what to submit and cancel. Rentile bounds concurrent exchanges, decoding, decoded-memory residency, and metatile workers without exposing a priority queue.

Status

Contract frozen, implementation beginning

The initial compatibility profile and architecture decisions are documented. The first public artifact is not yet available. Performance profiling is intentionally deferred until representative standalone rendering slices exist, while correctness, safety limits, determinism, and cancellation remain immediate gates.
